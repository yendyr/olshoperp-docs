# Create Return

> **Source:** [https://partner.tiktokshop.com/docv2/page/create-return-202602](https://partner.tiktokshop.com/docv2/page/create-return-202602)
> **Category:** Return and refund
> **document_path:** `create-return-202602`

## Description

Use this API to create a seller-initiated aftersales request for an order on behalf of the buyer. Supported request types are `REFUND` and `RETURN_AND_REFUND`. Before submitting the request, confirm that the order is eligible for the selected aftersales type and return method. After the request is created, use the relevant search, status, or review API to continue the aftersales workflow.

## Required scope

seller.fulfillment.basic, seller.return_refund.basic

## Path

`/return_refund/202602/returns`

## Method

`POST`

## Request Body

| Properties | Type | Required | Properties description |
| --- | --- | --- | --- |
| order_id | string | Y | Tiktok Shop order id |
| skus | []object | N | Skus |
| ^sku_id | string | Y | Sku id seller wants to create a return request |
| ^quantity | int | Y | Quantity of this SKU to include in the return request. |
| order_line_item_ids | []string | N | Specifies the order line IDs to include in the return request. Use this field to select order lines when an order is split into multiple packages. Do not provide non-empty values in both `order_line_item_ids` and `order_line_list` in the same request. If `order_line_item_ids`, `order_line_list`, and `skus` are all omitted, all order lines in the order are included. **Note:** This is a legacy field; new integrations should use `order_line_list` instead. |
| return_reason | string | Y | Seller's reason to create a return |
| return_type | string | Y | Which type to create: <br>- REFUND<br>- RETURN_AND_REFUND |
| refund_total | string | N | Total refund amount to the buyer. <br>The total refund amount can not exceed the refundable amount |
| currency | string | N | Currency of the refund amount. It should be the same as the currency of the TikTok Shop order. Required when `refund_total` is provided. |
| shipment_type | string | N | Specifies the return shipping method the buyer uses to send items back to the seller in a return request. Supported values:<br>- `PLATFORM`<br>- `BUYER_ARRANGE` |
| handover_method | string | N | **Optional**. Only applicable when shipment_type is `PLATFORM`. Specifies the handover method the buyer uses to return the item through platform-supported shipping. Supported values:<br>- `DROP_OFF`<br>- `PICKUP` |
| order_line_list | []object | N | Specifies the line items to include in the return request and supports bundle order splitting. Every entry must include `order_line_item_id`. For a bundle sub-item, also include `sub_order_line_item_id`; omit `sub_order_line_item_id` for a normal order line. Do not mix normal order lines and bundle sub-items in the same request. **Note:** This field is completely backward compatible with the legacy `order_line_item_ids` field. |
| ^order_line_item_id | string | N | The corresponding order line ID |
| ^sub_order_line_item_id | string | N | The sub-order-line ID inside a bundle product<br>- Required for bundle products<br>- Not required for non-bundle products |
