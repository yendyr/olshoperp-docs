# PENDING-20260826101500

## Catatan

- **Sumber skenario:** `npm run guard:scan -- --menu supplychain-new-purchase-inbound`
  (guard ★ no. 5). Aturannya terverifikasi ada di `requirement.md` §6 tabel *Qty vs PO*.

> [!IMPORTANT]
> **Temuan: guard backend ≠ perilaku UI.** Pesan backend
> `Input Quantity exceeds Outstanding PO. Max allowed: {n}` ADA di controller, tapi
> **tidak dapat dipicu dari UI** — dialog Create Inbound Product + tombol
> *Allocate Full Qty (Clearing)* membatasi alokasi ke outstanding sebelum request
> dikirim. Jadi guard itu hanya tercapai lewat jalur non-UI (API/import).
> Expected result TC ini disesuaikan ke perilaku AS-IS (clamp), bukan disalin mentah
> dari pesan backend — sesuai rule 13 §3A poin 2 (wajib verifikasi guard bisa dipicu
> dari UI) dan poin 3 (expected result mengacu requirement, bukan kode).
> Konsekuensi untuk penulis TC berikutnya: **hasil `guard:scan` adalah kandidat, bukan
> kebenaran final** — verifikasi dulu bagaimana UI benar-benar berperilaku.
- Test data diparameterisasi: outstanding qty datang dari PO yang dibuat di
  precondition, bukan dokumen statis. Automation membuat rantai PR → PO approved
  lebih dulu (fresh data), lalu mencoba melampaui outstanding-nya.
- Guard serumpun yang belum dibuat TC-nya (kandidat berikutnya di menu ini):
  *"Input Quantity must be greater than 0"*, *"Expired Date cannot be earlier than
  Transaction Date"*, *"Limit create serial number max 50"*.
