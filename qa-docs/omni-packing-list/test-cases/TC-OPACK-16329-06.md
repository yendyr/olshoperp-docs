# TC-OPACK-16329-06: [Packing List] - Void & Clone dari order cancel: TF return ke OUTRACK auto-approved, SO baru terbentuk, tanpa Shipping List

## Konteks Pengujian (Card ETM-16143 / Ref ETM-16329)
Memverifikasi dampak lintas modul (*cross-menu end-to-end integration*) saat eksekusi Void dan Void & Clone dari modal Packing List:
1. **Transfer Internal Otomatis:** Memastikan sistem meng-generate dokumen Transfer Return berstatus **Approved** yang mengembalikan stok barang ke lokasi **OUTRACK**.
2. **Status Sales Platform:** Order lama berstatus **Void**, dan order baru (hasil clone) aktif di Sales Platform.
3. **Pembersihan Logistik:** Tidak ada dokumen Shipping List yang terbentuk untuk pesanan yang dibatalkan.

## Precondition Data
1. Login Staging OlshopERP dengan privilege Packing List & Sales Platform Approval.
2. Catat jumlah stok awal produk uji di lokasi packing dan lokasi OUTRACK.
3. Tersedia 2 Packing List uji:
   * **Kasus 1:** Order Cancelled dari marketplace $\rightarrow$ untuk opsi **Void & Clone**.
   * **Kasus 2:** Order Void internal $\rightarrow$ untuk opsi **Void only**.

## Langkah Pengujian
1. Selesaikan Kasus 1 dengan opsi **Void & Clone (Recreate SO)**.
2. Selesaikan Kasus 2 dengan opsi **Void only**.
3. Buka menu **Transfer Internal**, periksa dokumen TF Return yang terbentuk.
4. Buka menu **Sales Platform**, verifikasi status order lama dan order baru.
5. Cek mutasi saldo stok di lokasi OUTRACK.

## Expected Result
* **TF Return:** Terbentuk otomatis berstatus `Approved` mengarah ke `OUTRACK`.
* **Stok OUTRACK:** Stok kembali utuh di OUTRACK.
* **Sales Platform:** Kasus 1 menghasilkan SO baru clone; Kasus 2 berstatus Void.
* **Logistik:** Bersih dari Shipping / Collecting List.
