# [TC-06] Expand Variant Group — child berelasi → leftover + confirm + SKU baru

**Kartu:** [ETM-15512](https://erpintegration.atlassian.net/browse/ETM-15512)  
**Docs:** `qa-docs/system-product/requirement.md` — **§6.3.2 GAP-SP-18** · related [ETM-15495](https://erpintegration.atlassian.net/browse/ETM-15495)  
**Tag automation:** `@TC-ETM-15512-06`

Child yang sudah punya relasi **tetap hidup** (leftover); semua kombinasi baru digenerate; wajib confirm popup.

## Precondition

- Master Default ON
- Parent/child Default sudah ada, contoh child `SKUPENSIL` (atau `ETM15512-E6-{stamp}`)
- Child **sudah punya relasi** minimal 1: SO / PR / PO / inbound / outbound / transfer / WO / binding / BOM / bundle (stok saja **bukan** syarat tunggal)
- Siapkan 2 group baru (total ≤ 3 termasuk Default), contoh:
  - Warna: `biru`, `hijau`
  - Motif: `doraemon`, `pikacu`

## Step

1. Edit parent Variant
2. Tambah Variant Group + opsi (Warna + Motif)
3. Save — amati **confirmation popup** leftover
4. **Skenario A:** Cancel → tidak commit expand
5. Ulangi → **Skenario B:** Confirm → commit
6. Cek daftar child di bawah parent yang sama

## Expected

- **Tidak** hard-block `Cannot add variant, Product already have relations`
- Confirm popup wajib sebelum commit leftover path
- Cancel: struktur child lama tidak berubah
- Confirm: leftover child lama **tetap Active** di bawah parent yang sama
- Semua kombinasi baru terbentuk sebagai product ID **baru**, contoh pola kartu:

```
SKUPENSIL                 ← leftover
SKUPENSIL-biru-doraemon   ← new
SKUPENSIL-hijau-doraemon  ← new
SKUPENSIL-biru-pikacu     ← new
SKUPENSIL-hijau-pikacu    ← new
```

- **Tidak** auto-rename leftover / child baru ke naming lain
- **Tidak** auto stock remap (stok leftover tetap di SKU lama; mapping manual via Stock Remapping)
- Inactive leftover hanya lewat existing inactive rules
